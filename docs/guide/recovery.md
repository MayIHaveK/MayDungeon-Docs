# 关服与异常恢复

MayDungeon 将服务器关闭视为本次副本结束，不会在重启后继续原来的怪物、阶段或倒计时。玩家的位置与游戏状态会被恢复，临时实例世界会被清理。

## 正常关服

请使用服务端的 `/stop` 命令，并等待进程完全退出：

1. 插件结束正在运行的副本。
2. 在线玩家返回进入副本前的位置。
3. 临时世界卸载并清理。
4. 下次启动后，玩家可重新进入副本。

不要在仍有实例运行时直接结束 Java 进程或删除 `instances/`。

## 崩服后该怎么做

1. 正常启动服务器，不要先手动删除插件数据目录。
2. 查看控制台是否报告残留副本会话或实例目录清理结果。
3. 让受影响玩家重新登录；插件会尝试恢复其进入副本前的位置和游戏状态。
4. 执行 `/md admin instances`，确认没有上次运行遗留的活跃实例。
5. 用一个测试账号重新进入并退出副本，确认地图创建与回收正常。

若玩家登录后仍在临时世界，先将其传送到安全大厅，再保留完整启动日志和该玩家 UUID 供排查。

## 存储配置

恢复数据跟随 `storage.type` 使用 YAML、SQLite 或 MySQL。更换存储类型不会自动迁移旧数据；应在停服状态下完成迁移或继续使用原后端。

```yaml
storage:
  type: yaml
  sqlite:
    file: "data/maydungeon.db"
  mysql:
    host: "localhost"
    port: 3306
    database: "maydungeon"
    username: "root"
    password: ""
    table-prefix: "md_"
```

## 备份建议

- 定期备份 `plugins/MayDungeon/`；MySQL 模式还需单独备份数据库。
- `maps/` 是模板地图，应纳入备份。
- `instances/` 是临时目录，不应作为地图源，也无需纳入长期备份。
- 更新插件或切换存储后端前先停服并备份。
